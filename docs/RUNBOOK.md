# Operations runbook

Everything runs on Cloudflare's free plan: one Worker (`arai`) serving the app
and `/api`, one D1 database (`arai`), and two Durable Object classes
(`FileStore` for encrypted chunks, `UserHub` for realtime). No card on file.

## Deploy
Automatic on every push to `main` or the development branch
(`.github/workflows/deploy.yml`): install → typecheck → lint → tests → build →
`wrangler d1 migrations apply arai --remote` → `wrangler deploy` → create any
missing server secrets. Check the run in GitHub Actions; a red run deploys
nothing. Manual run: Actions → Deploy → Run workflow.

## Secrets (Cloudflare only, never in git)
`AUTH_PEPPER`, `KDF_SALT_SECRET`, `IP_HMAC_SECRET` are generated by the first
deploy. **Never rotate `AUTH_PEPPER` or `KDF_SALT_SECRET`**: every password
hash and salt depends on them (everyone would be locked out). Rotating
`IP_HMAC_SECRET` only resets rate-limit buckets. Optional later:
`TURNSTILE_SECRET` + var `TURNSTILE_SITE_KEY` + `REQUIRE_TURNSTILE=true`,
`GIF_API_KEY` + `FEATURE_GIFS=on`.

## Optional providers (each feature stays greyed out until configured)
Public ids go in `apps/api/wrangler.jsonc` → `vars` (a deploy overwrites
variables set only in the dashboard); secrets via `npx wrangler secret put NAME`
in `apps/api`.

**Dropbox** (users store audio in their own Dropbox):
1. https://www.dropbox.com/developers/apps → Create app → Scoped access → **App folder** → name it e.g. `Arai`.
2. Permissions: `files.content.write`, `files.content.read`, `sharing.write`, `sharing.read` → Submit.
3. Settings: Redirect URI `https://arai.ranuj-s.workers.dev/storage/callback`; *Allow public clients (Implicit Grant & PKCE)*: Allow.
4. Copy the **App key** into `vars.DROPBOX_APP_KEY`. No secret is needed (PKCE). New apps allow 500 users until you apply for production.

**Google Drive**:
1. https://console.cloud.google.com → new project → enable **Google Drive API**.
2. OAuth consent screen: External, scope `.../auth/drive.file`; add yourself as a test user (publish it to open it to everyone).
3. Credentials → OAuth client ID → Web application → redirect URI `https://arai.ranuj-s.workers.dev/storage/callback` → put the client id in `vars.GOOGLE_CLIENT_ID`, the client secret via `wrangler secret put GOOGLE_CLIENT_SECRET`.
4. Credentials → API key restricted to the Drive API → `wrangler secret put GOOGLE_API_KEY` (lets Arai read the shared ciphertext files).

**GIFs**: a GIF provider key as `GIF_API_KEY` + `vars.FEATURE_GIFS = "on"`.

## Backups
- **D1 Time Travel** (built in, free): any minute in the last 30 days.
  `npx wrangler d1 time-travel info arai --timestamp=<ISO time>` shows the
  bookmark; `npx wrangler d1 time-travel restore arai --bookmark=<id>` restores
  the whole database (destructive: take an export first).
- **Weekly export** (keep offline, it contains only ciphertext, hashes and
  public data): `npx wrangler d1 export arai --remote --output=arai-YYYY-MM-DD.sql`.
- **Audio chunks** live in Durable Object storage, which Cloudflare replicates;
  there is no export tool on the free plan. If a chunk is lost the file shows
  as failed; the uploader still has the original. Documented limitation.

## Restore drill (do once before launch, then quarterly)
1. Export the database. 2. Create a scratch D1 (`wrangler d1 create arai-drill`).
3. `wrangler d1 execute arai-drill --remote --file=arai-YYYY-MM-DD.sql`.
4. Run `node scripts/admin.mjs verify-audit` against it (edit the name) and
   check row counts. 5. Delete the scratch database.

## Incidents
1. **Contain**: suspend accounts from the dashboard (signs them out
   everywhere); hide public projects; revoke share links (project owners) or
   set `revoked_at` in D1 for many at once.
2. **Credential leak of the Cloudflare token**: revoke it in Cloudflare →
   create a new one → update the GitHub secret `CLOUDFLARE_API_TOKEN`.
3. **Suspected server compromise**: private content stays encrypted (the
   server never had the keys), but a modified app could capture keys from
   users who load it afterwards. Redeploy from a known-good commit, rotate the
   API token, review `audit_log` (`node scripts/admin.mjs verify-audit`), tell
   users what happened.
4. **Abuse spike**: rate limits are in D1 (`rate_limits`); turn on Turnstile.
5. Record what happened and what changed in `docs/SESSION_LOG.md`.

## Capacity (free plan)
Storage cap is set by `PLATFORM_QUOTA_BYTES` (4.5 GB of the 5 GB DO limit) and
`USER_QUOTA_BYTES` (500 MB each). Uploads stop cleanly when the platform is
full. The dashboard shows usage. D1: 5 GB, 5 M reads/day, 100 k writes/day.
